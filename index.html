Data Analytics & Visualization Capstone

University analytics dashboards

Four dashboards built for a university Provost's office. Three run on real IPEDS data from the U.S. Department of Education — each answering exactly one question, with a hard no-synthetic-data rule. The fourth is the full-breadth prototype that made the case for narrowing.

01 Runs locally

Institutional Data Dashboard

What does a full-breadth university analytics dashboard look like, end to end?

Six tabs over one shared filter state — enrollment, academics, courses, admissions, finance, and drill-down. Built on synthetic data to exercise layout, filtering, and branding before scope narrowed. The control case for everything after it.

02 Live

PhD Completions Dashboard

How many CS and Math doctorates does YU produce, compared to five peers?

Doctoral completions 2015–2024 across six institutions. Its analytical core: two institutions sit at zero in Computer Science for structurally different reasons — one a new program, one with no doctoral records at all — and the dashboard is built so those two zeros can never be read as the same story.

03 Live

Institutional Resources Dashboard

How resource-intensive is YU compared to peers, and how has that changed?

Instruction spending per student, FY2015–2024, against five private peers. All six are FASB filers — the condition IPEDS itself requires for a valid comparison. The measure is published by IPEDS, not computed here. PostgreSQL is the authoritative store; the shipped JSON is a generated artifact.

04 Runs locally

Peer Tuition Dashboard

How does YU's published tuition compare to peers, by level, over a decade?

Published tuition AY2015–16 through AY2024–25. Undergraduate and graduate figures are never blended — no such number exists in IPEDS, and inventing one would be synthetic data by another name. Required fees are an opt-in toggle, so they never silently inflate the headline.

Streamlit · Plotly · PostgreSQL·IPEDS Cost

Repository

Why two run locally. GitHub Pages serves static files only. Projects 02 and 03 are static React builds, so they deploy directly. Projects 01 and 04 are Streamlit apps that need a live Python process — and 04 additionally queries a PostgreSQL database — so both require a Python host rather than Pages. Each repository's README covers how to run it.
